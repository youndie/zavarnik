# docs — zavarnik

Gradle-плагин, который тренирует, проверяет и упаковывает AOT-кэш Project Leyden для обычного
JVM-приложения на плагине `application`. Документация слоёная; ссылки идут сверху вниз.

```
[ Research (почему архитектура такая) ]
                     │
[ Feature (бизнес + BDD) ] ──▶ [ Service (модуль плагина, сборка, публикация) ]
```

| Слой | Каталог | Отвечает на | Источник истины |
|---|---|---|---|
| Research | `research/` | *почему* так; что проверено, что гипотеза | артефакты, которые называет каждый факт: журналы в `experiments/`, исходники HotSpot, JEP |
| Feature | `features/` | *что* делает плагин и *зачем*; BDD-сценарии | этот репозиторий — появится вместе с кодом |
| Service | `services/` | модули, сборка, публикация, локальный запуск | этот репозиторий — появится вместе с кодом |

Слоёв `screens/` и `api/` нет и не будет: у плагина нет ни клиента, ни HTTP-поверхности.
Отсутствующий каталог — ответ; переименованный — нет.

**Бэклог** — [backlog.md](../backlog.md): индекс и решения; задачи — по файлу в
[`backlog/`](backlog/), цитируются как [B-06](backlog/B-06-aot-verify-task.md).

## Соглашения

- **`id`** в frontmatter уникален и равен имени файла.
- Связи между слоями — id в frontmatter и обычные markdown-ссылки в тексте.
- Один документ — одна сущность.
- BDD-сценарии пишутся по наблюдённому поведению: настоящие строки журнала JVM, настоящие коды
  выхода. Пока кода нет, сценарий помечен *target*.
- **Главный читатель — агент.** Каждый документ несёт якоря: пути в код или в артефакт проверки.
  Что живёт в коде (DSL, ключи конфигурации), не копируется — даётся путь.
- Язык: русский. Идентификаторы, флаги JVM, URL и строки журналов — дословно, как в коде.

## Шаблоны

`templates/` — копии шаблонов документов, чтобы формат ехал вместе с репозиторием. Секции с
пометкой `<!-- optional -->` можно удалять.
