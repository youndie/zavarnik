# B-24 — `aotReport`: кривая прогрева и работа JIT

Ресёрч §1.9 (07.09.2026): кэш экономит ~10 % компиляций после старта, остальное JIT делает
заново; `aotReport` меряет только время до первого `200` и создаёт впечатление «тёплого» сервиса,
которого нет. Отчёт обязан показывать обе вещи, иначе пользователь плагина ждёт не того.

- **Решение: две дополнительные строки в отчёте.** (1) Работа JIT за первые N секунд нагрузки
  на `readyWhen.url` (или на шаги `workload`): число методов C1/C2 и время — из `-XX:+CITime`
  при выходе или из JFR `jdk.Compilation`; холодный против кэша. (2) rps по окнам после
  готовности — только на машине, где частота стабильна; на мобильном чипе отчёт должен
  предупредить, а не рисовать шум.
- Отвергнуто: молчать про прогрев, раз плагин его не даёт. Ровно наоборот: честное «после старта
  JIT сделает 90 % работы» — это то, что отличает отчёт от рекламы.
- Не покрывает: AOT-компиляцию кода (JEP 8335368) — когда она выйдет, отчёт покажет разницу сам.

- AC: `aotReport` печатает таблицу компиляций C1/C2 за окно нагрузки для обоих вариантов;
  README образца показывает её рядом с готовностью.
- Якоря: `zavarnik-gradle-plugin/src/main/kotlin/io/github/youndie/zavarnik/AotReportTask.kt`,
  `experiments/jit-warmup/citime.sh`, `docs/research/research-architecture.md` (§1.9).
